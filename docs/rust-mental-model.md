# KawaGiif — a mental model of the Rust backend

How to think about what the Rust side does, in the order it's worth learning.
The full map of modules, functions, inputs and relations (Rust and React) is
in [architecture.svg](architecture.svg).

The diagram is generated by [gen-architecture.mjs](gen-architecture.mjs): the
boxes, rows and edges are data at the top of that file, and the layout and
wire routing are computed. It does not parse the source, so after changing a
module, edit its entry there and run `npm run docs:diagram`.

---

## 1. The one-sentence model

> **Rust owns the state, the windows and the disk. React only draws and asks.**

Everything that must survive, be shared between windows, or touch the OS
(Win32, files, the tray, global shortcuts) lives in Rust. Each React window is
a thin view that:

- **asks** Rust with `invoke("command", args)` — request/response, like a function call that crosses a process boundary;
- **listens** to Rust with `listen("event")` — Rust pushes a notification with `emit` (to everyone) or `emit_to` (to one window).

```
React ──invoke("spawn_placed_media", {mediaId})──▶ #[tauri::command] fn spawn_placed_media(...)
React ◀──────emit("placed-items-changed")──────── notify_placed_items_changed(&app)
```

If you keep only one rule in mind: **when you wonder "where does X live?", the
answer is almost always "in a Rust `State`, and React fetches a copy".**

## 2. Lifecycle: from `main()` to exit

`main.rs` only calls `kawagiif_lib::run()`. Everything happens in `lib.rs::run()`,
in this order:

1. **Register shared state** with `.manage(...)`:
   `EditorState`, `LibraryState`, `SysState`. From now on any command can ask
   for them as `State<EditorState>` etc.
2. **Plugins**: `dialog` (Open-file dialog), `autostart` (Windows registry),
   `global-shortcut` with a handler: `Ctrl+Alt+Esc` → `release_all_click_through`.
3. **`generate_handler![...]`**: the list of every function React may `invoke`.
   A `#[tauri::command]` that is not here does not exist for the frontend.
4. **`setup()`** — runs once, on the main thread, before the event loop:
   1. `window_manager::create_control_window` (hidden).
   2. `window_manager::create_overlay_pool` — creates **all** overlay windows (`OV-SLOT-0..N`), hidden.
   3. Hooks the control window's X button → `handle_control_close`.
   4. `template::spawn_saved_template_on_boot` — reads `template.json` and shows the saved animations, click-through.
   5. Registers the `Ctrl+Alt+Esc` shortcut.
   6. `tray::setup` — tray icon + menu.
   7. `window_manager::spawn_topmost_keeper` — background thread, every 2 s.
   8. Shows the control window unless `start_minimized_to_tray`.
5. **Event loop** (`.run(...)`): on `RunEvent::ExitRequested` → `handle_exit`
   (discard unsaved edits, hide every overlay).

The X button never quits. Only **Tray → Quit** (`app.exit(0)`) does.

## 3. The layers

Read the modules top to bottom. Each one only calls the ones below it.

| Layer | Module | What it is | Think of it as |
|---|---|---|---|
| Wiring | `lib.rs` | Builder, plugins, `setup`, close/exit policy | `main` |
| Entry points | `commands.rs`, `tray.rs` | Small commands (settings, control window), tray menu | thin adapters |
| Domain + state | `template.rs` | Placed animations, editor state, slot assignment | the brain |
| Domain + state | `library.rs` | Imported media, tags | the catalogue |
| Window ops | `window_manager.rs` | Pool of windows, show/hide/move, styles | the stage hand |
| OS | `native/windows.rs` | Raw Win32 (`unsafe`) | the screwdriver |
| Foundations | `config.rs`, `error.rs`, `system_stats.rs` | Settings file, atomic writes, error type, RAM | the toolbox |

**One exception to "only downward"**: `window_manager::watch_overlay_events`
calls `template::update_slot_geometry` when the user drags or resizes an
overlay. `window_manager` knows about *slots* (window numbers); only `template`
knows which *animation* a slot shows, so it has to call back up.

## 4. Shared state

There are three pieces of global, mutable state. All follow the same pattern:

```rust
pub struct EditorState(Mutex<Editor>);           // newtype around a Mutex

impl EditorState {
    pub fn lock(&self) -> MutexGuard<'_, Editor> {
        self.0.lock().unwrap_or_else(PoisonError::into_inner)
    }
}
```

- `Mutex` because Tauri may run commands on several threads.
- `unwrap_or_else(PoisonError::into_inner)`: if a thread panicked while holding
  the lock, keep using the data instead of crashing every later call.
- The guard (`MutexGuard`) releases the lock when it goes out of scope (or on `drop(guard)`).

| State | Inside | Lives in | Persisted to |
|---|---|---|---|
| `EditorState` | `Editor { working, saved, selected, edit_mode, slots }` | `template.rs` | `template.json` (only `saved`) |
| `LibraryState` | `LibraryIndex { schema_version, items: Vec<MediaItem> }` | `library.rs` | `library_index.json` |
| `SysState` | `sysinfo::System` (cached sampler) | `system_stats.rs` | — |

Plus three **compute-once values** with `OnceLock` (no lock needed after init):
`config::data_dir()`, `window_manager::pool_size()`, `window_manager::slot_labels()`.

Settings (`AppConfig`) are **not** kept in memory: `config::load()` reads
`config.toml` each time, `config::update(|c| ...)` reads, changes and writes it.

## 5. The key ideas

### 5.1 The overlay pool and slots

A transparent window created after startup is born without `WS_EX_LAYERED`
(no real transparency). So **all overlay windows are created in `setup()`** and
reused:

```
slots: Vec<Option<Uuid>>      // index = window OV-SLOT-n, value = instance shown
         [Some(a), None, Some(c), None, ...]
```

- `alloc_slot(id)` → first `None` becomes `Some(id)`; full → `AppError::PoolFull`.
- `free_slot(id)` → back to `None`.
- "Placing" an animation = alloc a slot + `window_manager::show_slot` (move, size, show) + tell that window which instance it shows (`slot-assigned`).
- Slots are not saved: on restart they're handed out again in template order.
- **Free slots sleep.** Each window is its own WebView2 renderer process, so an empty slot used to cost as much as a busy one. When a slot is freed, Rust emits `slot-released`; the overlay page drops its media and answers with `overlay_idle`; Rust then makes that webview dormant (`window_manager::set_slot_dormant` → `native::set_webview_dormant`: hidden, low memory target, `TrySuspend`). `show_slot` wakes it before showing it. The window is never destroyed, so `WS_EX_LAYERED` survives.

Two different IDs, don't mix them up:
- `media_id` — a file in the library (`MediaItem.id`).
- `instance_id` — one placement of that file on the desktop (`PlacedMedia.instance_id`). The same GIF can be placed three times.

### 5.2 Working vs saved template

`Editor` keeps two copies of `Template`:

- `working` — what the editor is changing right now.
- `saved` — what is on disk.

`is_dirty()` is just `working != saved` (derived `PartialEq`).
**Save** = write `working` to disk and copy it into `saved`.
**Discard** = copy `saved` into `working` and respawn the overlays.

### 5.3 Edit mode

`set_edit_mode(true)` (when the Editor screen mounts):
overlays stop being click-through, styles reapplied, control window made
always-on-top and raised above the overlays. `set_edit_mode(false)` reverses
it and clears the selection. Geometry changes (`update_slot_geometry`) are
**only recorded in edit mode**.

### 5.4 One unit: physical pixels

`Moved`/`Resized` events report physical pixels, so everything stored in
`PlacedMedia` (x, y, width, height) is physical. Template schema v1 used
logical pixels; `load_template_from_disk` migrates by the monitor scale factor.

### 5.5 Never a half-written file

`config::write_atomic(path, bytes)` writes `<path>.tmp` then renames it over
the real file. Every save in the app (config, template, library) goes through it.

### 5.6 One error type

Every fallible command returns `AppResult<T>` = `Result<T, AppError>`.
`#[from]` on the variants lets `?` convert `io::Error`, `serde_json::Error`,
`tauri::Error`… automatically. `AppError` serializes as its `Display` text, so
React receives a plain string. `MediaReferenced(n)` → `"REFERENCED:n"` is a
contract: `LibraryProvider.parseReferencedError` parses it.

## 6. The lock rule (read this before touching `template.rs`)

> **Never hold the `EditorState` lock while calling `window_manager`.**

Why: `window.set_position()` / `set_size()` / `show()` fire `Moved`/`Resized`
**synchronously**. Their handler is `update_slot_geometry`, which calls
`state.lock()`. A `std::sync::Mutex` is not re-entrant → the thread waits for
itself → deadlock.

So the code always does: lock in a small block, copy out what's needed, let
the guard drop, *then* touch windows:

```rust
let slot = {
    let mut editor = state.lock();
    editor.alloc_slot(item.instance_id)?    // guard dropped at `}`
};
window_manager::show_slot(app, slot, ...)?;  // safe: no lock held
```

Second rule: **never hold the editor lock and the library lock at the same
time** (see `list_placed_items` and `delete_media` — one after the other).

## 7. Flows, step by step

### 7.1 App boot
`run()` → `setup()` → `create_overlay_pool` (N hidden windows, each with
`watch_overlay_events`) → `spawn_saved_template_on_boot` → for each saved item
`place_item_in_slot(.., interactive=false)` → `show_slot` → `emit_to(slot, "slot-assigned")`.
In each overlay, `OverlayItemApp` already asked `get_instance_id_for_window`
on mount and also listens to `slot-assigned` → `loadPlacedMedia` →
`get_placed_media` + `list_media` → `useMediaUrl` → `get_media_path` →
`convertFileSrc` → `asset://` URL → `<video>/<img>/GifCanvasPlayer`.

### 7.2 Placing an animation from the editor
1. `MediaSidebar` mousedown → `invoke("spawn_placed_media", {mediaId})`.
2. Rust builds a `PlacedMedia` (220×220 at 120,120), `place_item_in_slot(.., true)`, pushes it to `working.items`, emits `placed-items-changed`, returns `{instance_id, window_label}`.
3. React calls `Window.getByLabel(label).startDragging()` → the user drags the new window immediately.
4. The overlay loads the media; on first `loadedmetadata`/`load` it calls `fit_overlay_to_media(naturalWidth, naturalHeight)` → Rust resizes to the real aspect ratio once (`auto_sized = true`).

### 7.3 Dragging / resizing an overlay
Windows moves the window itself → `WindowEvent::Moved` →
`clamp_to_work_area` (if it had to correct, a new `Moved` comes) →
`template::update_slot_geometry(slot, pos)` → updates `working` →
`emit_to(control, "overlay-geometry-changed", instance_id)` →
`useEditorSync` marks it as moved → `EditorScreen.syncMinimizable` →
`has_unsaved_changes` → `set_control_minimizable(!dirty)`.
Resizing: the overlay's handle sends `resize_overlay(w, h)` per animation frame → `Resized` → same path. Arrow keys → `nudge_overlay(dx, dy)`.

### 7.4 Save / discard
- Save: `save_template` → `save_template_to_disk(working)` → `saved = working`.
- Discard: `discard_template_changes` → `working = saved` → `respawn_overlays_from(saved, edit_mode)` → `placed-items-changed`.
- Leaving the editor (or pressing X) while dirty: `ControlApp.requestExit` asks `has_unsaved_changes` → modal Save/Discard/Cancel. The X goes through Rust first: `handle_control_close` emits `close-requested` instead of hiding.

### 7.5 Deleting media that is placed
`StorageScreen` → `deleteMedia(id, false)` → `delete_media` →
`count_references_to_media > 0` → `Err(MediaReferenced(n))` → React parses
`REFERENCED:n`, asks the user → `delete_media(id, force=true)` → removes the
file and the index entry → `template::purge_media_references` (removes from
`working` *and* `saved`, frees slots, rewrites `template.json`) →
`library-changed` + `placed-items-changed`.

### 7.6 Recovering from click-through
With click-through on, overlays can't get focus, so a local key listener never
fires. `Ctrl+Alt+Esc` is a **global** shortcut → `release_all_click_through` →
`set_overlay_click_through(false)` on all overlays + `click-through-changed`.

### 7.7 Panic button and quit
- Home / Tray → **Kill all animations** → `kill_all_overlays` → `release_all_slots` (template untouched; they come back next time the editor opens or the app starts).
- Tray → **Quit** → `app.exit(0)` → `ExitRequested` → `handle_exit`.

## 8. Why `native/windows.rs` exists

Tauri sets some window styles unreliably and resets others on its own.
`window_manager::reapply_overlay_style` calls all of these:

| Function | Fixes |
|---|---|
| `force_hide_from_taskbar` | `skip_taskbar(true)` is buggy and Tauri re-runs it on focus → remove `WS_EX_APPWINDOW`, add `WS_EX_TOOLWINDOW` |
| `force_borderless` | `decorations(false)` gets undone → strip caption/frame/edge bits + `SWP_FRAMECHANGED` |
| `disable_dwm_focus_border` | Windows 11 accent border and rounded corners (drawn by DWM, outside CSS reach) |
| `ensure_layered` | `set_ignore_cursor_events(false)` removes `WS_EX_LAYERED` → grey opaque frame |
| `clear_class_background` | white class brush flashes before WebView paints |
| `raise_to_top` | re-stack at top of the topmost band |
| `work_area_for` | monitor rect minus taskbar, for `clamp_to_work_area` |

It's reapplied on **create, every `show_slot`, `Focused`, edit-mode changes,
and every 2 s by the keeper**, because a click-through overlay never gets
focus, so the focus hook alone would never fire for it.

All functions take an `HWND` from `window.hwnd()` on a living window owned by
this process, on the main thread — that's what makes the `unsafe` blocks sound.
Every caller is wrapped in `#[cfg(windows)]`.

## 9. Events catalogue (Rust → React)

| Event | Emitted by | Target | Listened by |
|---|---|---|---|
| `library-changed` | `library::notify_library_changed` | all | `LibraryProvider` → `refresh` |
| `placed-items-changed` | `template::notify_placed_items_changed` | all | `PlacedItemsList`, `EditorScreen` |
| `selection-changed` | `select_overlay`, `notify_selection_cleared` | all | `useEditorSync`, `PlacedItemsList`, `OverlayItemApp` |
| `overlay-geometry-changed` | `update_slot_geometry` | control | `useEditorSync` |
| `close-requested` | `lib::handle_control_close` | control | `ControlApp` |
| `slot-assigned` | `place_item_in_slot` (`emit_to_slot`) | one overlay | `OverlayItemApp` (`"self"`) |
| `slot-released` | `release_slot_for_instance`, `release_all_slots` | one overlay | `OverlayItemApp` (`"self"`) → `overlay_idle` |
| `edit-mode-changed` | `place_item_in_slot`, `set_edit_mode` | one overlay | `OverlayItemApp` (`"self"`) |
| `item-opacity-changed` | `update_item` via `set_item_opacity` | one overlay | `OverlayItemApp` (`"self"`) |
| `item-playback-rate-changed` | `update_item` via `set_item_playback_rate` | one overlay | `OverlayItemApp` (`"self"`) |
| `click-through-changed` | `lib::release_all_click_through` | each overlay | (not consumed yet) |

`emit` broadcasts to every window. For per-overlay events Rust uses `emit_to`
**and** React listens with `listenToSelf` (`getCurrentWebviewWindow().listen`),
because a plain `listen` also receives everything.

## 11. Rust patterns you'll meet in this code

| Pattern | Example | Meaning |
|---|---|---|
| `?` | `index.save()?` | return the error early, converting it with `From` |
| `ok_or(...)` | `.ok_or(AppError::MediaNotFound(id))?` | `Option` → `Result` |
| `let … else` | `let Some(item) = editor.item_mut(&id) else { return; };` | unwrap or leave |
| Scoped lock block | `let x = { let e = state.lock(); … };` | release the lock before the next step |
| `FnOnce` closure param | `config::update(\|c\| c.x = v)`, `update_item(.., \|item\| …)` | caller says *what* to change, function does load/save |
| Generic with bounds | `emit_to_slot<S: Serialize + Clone>` | any payload that can be sent |
| `impl Iterator + '_` | `overlay_windows(app)` | lazy iterator borrowing `app` |
| `OnceLock` | `pool_size()` | lazy global computed once |
| `#[cfg(windows)]` / `#[cfg(debug_assertions)]` | native calls / dev logs | compiled only on Windows / in debug |
| `#[serde(default)]` | `auto_sized`, `tags` | old JSON files without the field still load |
| `std::mem::take` | `normalize_tags(std::mem::take(&mut item.tags), …)` | move out, leave an empty `Vec` |
| `retain` | `items.retain(\|i\| i.media_id != id)` | delete in place by condition |

## 12. Checklist: adding a feature

1. **Where does the data live?** New field in an existing state (`Editor`, `PlacedMedia`, `AppConfig`) or a new `State` registered with `.manage()` in `lib.rs`. New field on something persisted → `#[serde(default)]`.
2. **Write the command** in the module that owns that state. Lock briefly; never call `window_manager` while locked.
3. **Register it** in `generate_handler!` in `lib.rs`.
4. **Permissions**: core window APIs used from JS need an entry in `src-tauri/capabilities/control.json` or `overlay.json`.
5. **Who else must know?** `emit` (everyone) or `emit_to` (one window) after the change.
6. **React**: `invoke("name", { camelCaseArgs })` through `src/lib/ipc.ts`, and `useTauriEvent("event", handler, "self" | "any")`. Add a mock to `MOCK_RESPONSES` if the browser-only mode needs it.
7. Errors: add an `AppError` variant if the UI must react to it specifically.
